# K12 知识库文档生成提示词体系

给 AI 工具（workbuddy / trae / zcode 等）使用的分层提示词：按「通用规范 + 学段 + 学科」三层拼接，生成符合知识库「文档录入」要求的纯 Markdown 知识文档。

## 使用方法（三层拼接）

1. 打开 `00-通用规范.md`；
2. 按教材所在学段，打开对应学段文件；
3. 按教材学科，打开对应学科文件；
4. 三份文件按顺序拼接，末尾填好「本次任务参数」（教材全名、学段、学科、整理范围）；
5. 整段发给 AI 工具，一次生成一个单元（约 3000-6000 字）。

## 入库流程（管理端「文档录入」）

生成的正文**不含 frontmatter**，元数据全部在录入表单填写：

1. **建知识点**：管理端「知识库 → 知识目录 → 新增知识点」，填名称、学段、学科、难度（学科在此选择，决定目录树归属）。知识点粒度建议 = 单元，如「语文·二年级下册·第一单元」；
2. **文档录入**：知识目录页「文档录入」→ 填标题（如「语文二年级下册·第一单元（春天）」）、学段、知识点、难度、状态上架 → 正文粘贴生成的 md → 右侧预览核对标题层级、表格与 LaTeX 渲染 → 保存；
3. 提交后后端自动向量化，列表「入库状态」：待处理 → 处理中 → 已入库；失败时点该行「重新入库」。

## 注意事项

- 正文不带任何 frontmatter/元数据头；
- 一级标题（#）是系统分块边界：每个知识点（课）一个一级标题，检索粒度即到课；
- 单篇建议 ≤8000 字，过长就再拆分录入；
- 数学/科学公式务必在预览里确认渲染（MathMarkdown 支持 $...$ 与 $$...$$）；
- 录入前对照资源中心的教材 PDF 抽查生字表、课文细节——生成模型可能存在记忆偏差，不确定处文档内已标「（以本教材为准）」。

## 设计缘由

- 「AI 文档整理」（上传 PDF → 解析 → 分段整理）慢且耗 token，且 6000 字符分段拼接必然产生标题重复、内容截断与目录/版权页噪声（实测语文二年级上册 PDF 产出 12 段，每段独立大标题，课文多处截断）；
- 「扫描目录导入」（importDir）前端入口已移除，不再使用；
- 「文档录入」直接粘贴：生成快、元数据可控（学段/知识点/学科在表单选择）、逐篇预览质检，是当前批量填充数据的标准路径。
